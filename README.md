# Домашнее задание №2: Приложение для ведения учебных групп и студентов

Репозиторий содержит веб-приложение на базе актуальной версии фреймворка **Laravel** для управления учебными группами и студентами. Проект выполнен в отдельной ветке `homework-2` в соответствии с требованиями технического задания.

---

## 1. Информация о развернутом окружении

- **Версия фреймворка (`laravel/framework`)**: `v13.42.0` (актуальная стабильная версия)
- **Версия PHP**: `8.5.10`
- **Версия Composer**: `2.11.2`
- **База данных**: SQLite (`database/database.sqlite`)
- **Ветка репозитория**: `homework-2`

## 2. Выполненные требования задания

### 2.1. Конфигурация базы данных SQLite
- В файле `.env` настроено подключение к SQLite:
  ```dotenv
  DB_CONNECTION=sqlite
  ```
- Создан файл базы данных: `database/database.sqlite`.

### 2.2. Миграции и модели
С помощью команды `php artisan make:model <Name> -m` сгенерированы модели и миграции со строгой типизацией:

1. **Таблица `groups` (Модель `Group`)**:
   - `id` — первичный автоинкрементный ключ (`id()`);
   - `title` — название группы (строка `string`);
   - `start_from` — дата начала обучения (`date`);
   - `is_active` — статус начала обучения группы (`boolean`, по умолчанию `false`);
   - `created_at`, `updated_at` — временные метки (`timestamps()`).

2. **Таблица `students` (Модель `Student`)**:
   - `id` — первичный автоинкрементный ключ (`id()`);
   - `group_id` — внешний ключ на таблицу `groups` с каскадным удалением (`foreignId('group_id')->constrained()->cascadeOnDelete()`);
   - `surname` — фамилия студента (`string`);
   - `name` — имя студента (`string`);
   - `created_at`, `updated_at` — временные метки (`timestamps()`).

### 2.3. Настройка отношений Eloquent
- В модели `Group` реализована связь «один ко многим»:
  ```php
  public function students(): HasMany
  {
      return $this->hasMany(Student::class);
  }
  ```
- В модели `Student` реализована обратная связь «многие к одному»:
  ```php
  public function group(): BelongsTo
  {
      return $this->belongsTo(Group::class);
  }
  ```
- В обеих моделях настроены поля `$fillable` для безопасного массового заполнения, а в модели `Group` — кастинг атрибутов (`casts()`): `start_from => date`, `is_active => boolean`.

### 2.4. Ресурсные контроллеры и маршрутизация
С помощью `php artisan make:controller` сгенерированы ресурсные контроллеры `GroupController` и `StudentController` (с привязкой к родительской модели `Group`).

Маршруты зарегистрированы в `routes/web.php` в точном соответствии с техническим заданием:

| Метод | Маршрут | Имя маршрута | Описание | Примечание |
|---|---|---|---|---|

| `GET` | `/groups/create` | `groups.create` | Отображает страницу для создания новой группы | Форма с валидацией полей |

- Создан базовый макет `resources/views/layouts/app.blade.php` с современным адаптивным дизайном, панелью навигации, хлебными крошками и блоками уведомлений об успехе / ошибках валидации.
- Страницы просмотра (`groups.show`, `students.show`) отображают **всю информацию из базы данных**: идентификаторы, названия, даты начала, статусы активности, даты создания и обновления записей.
- Реализованы ссылки навигации: «Назад ко всем группам», «Назад к группе», кнопки добавления сущностей.

## 3. Ответы на контрольные вопросы

### Вопрос 1: Для чего нужны миграции? Какую роль они играют или какую проблему решают?

**Миграции в Laravel** — это специализированная система контроля версий для структуры базы данных (своего рода Git для схемы БД). Они позволяют разработчикам описывать, изменять и версионировать структуру таблиц с помощью выразительного объектно-ориентированного PHP-кода (классы `Schema` и `Blueprint`), не прибегая к ручному написанию специфичных для конкретной СУБД SQL-скриптов.

#### Ключевые проблемы, которые решают миграции:

1. **Синхронизация схемы БД в команде разработчиков**:
   - *Проблема*: Без миграций разработчикам приходилось передавать друг другу ручные SQL-дампы (`dump.sql`) или текстовые инструкции («создай таблицу X», «добавь колонку Y в таблицу Z»). Это неизбежно приводило к человеческим ошибкам, расхождениям в схемах баз данных на разных машинах и сбоям вида «у меня всё работает, а у коллеги ошибка: column not found».
   - *Решение*: Миграции хранятся в репозитории как исходный код. Каждый разработчик после получения свежей ветки (`git pull`) запускает стандартную команду `php artisan migrate`, и его локальная база данных автоматически приводится к актуальному состоянию.

2. **Автоматизация и безопасность деплоя (CI/CD и Production)**:
   - *Проблема*: Ручное накатывание изменений схемы на рабочем сервере сопряжено с высоким риском опечаток, пропущенных изменений и простоя сервиса.
   - *Решение*: В пайплайне деплоя выполняется команда `php artisan migrate --force`, гарантирующая строго последовательное, идемпотентное и предсказуемое применение изменений.

3. **Возможность контролируемого отката (Rollback)**:
   - *Проблема*: Если при релизе нового функционала обнаружена критическая ошибка, вручную вернуть структуру базы данных назад быстро и без потерь практически невозможно.
   - *Решение*: Каждая миграция содержит симметричные методы: `up()` (применение изменений) и `down()` (их отмена). Команда `php artisan migrate:rollback` позволяет моментально отменить последний пакет изменений (batch).

4. **Абстракция от конкретной СУБД (Database Agnostic)**:
   - *Проблема*: Различные СУБД (PostgreSQL, MySQL, SQLite, SQL Server) имеют разные диалекты SQL, типы данных и синтаксис внешних ключей.
   - *Решение*: Метод `$table->string('title')` или `$table->foreignId('group_id')` генерирует правильный SQL для любой поддерживаемой СУБД, что позволяет легко менять движок базы данных (например, SQLite для тестов и PostgreSQL для production) без переписывания схемы.

5. **Изоляция и воспроизводимость автотестов**:
   - Автоматические тесты с трейтом `RefreshDatabase` используют миграции для создания свежей базы данных в оперативной памяти (`:memory:`) или временном файле перед запуском тестов, обеспечивая полную изоляцию и чистоту тестового окружения.

### Вопрос 2: Для чего нужен Eloquent ORM?

**Eloquent ORM** — это встроенная в Laravel объектно-реляционная модель (Object-Relational Mapping), реализующая популярный архитектурный шаблон проектирования **Active Record**. 

В этой модели:
- Каждая **таблица** базы данных сопоставляется с отдельным **PHP-классом (моделью)** (например, таблица `groups` ↔ класс `Group`, таблица `students` ↔ класс `Student`).
- Каждая **строка** таблицы представляет собой **экземпляр (объект)** этого класса.
- Столбцы таблицы становятся **свойствами** этого объекта.

#### Зачем нужен Eloquent ORM и какие задачи он решает:

1. **Абстракция от низкоуровневого SQL и повышение читаемости кода**:
   - Вместо написания громоздких и чреватых синтаксическими ошибками строк SQL (`"SELECT * FROM students WHERE group_id = " . $id`), разработчик работает с данными на чистом объектно-ориентированном языке:
     ```php
     $students = Student::where('group_id', $group->id)->get();
     ```
   - Создание, изменение и удаление записей выполняется интуитивными вызовами методов:
     ```php
     $group = Group::create(['title' => 'FS-01', 'start_from' => '2023-01-10']);
     $group->is_active = true;
     $group->save();
     ```

2. **Декларативное управление отношениями (Relationships)**:
   - Eloquent предоставляет простой и выразительный синтаксис для связывания таблиц между собой: один к одному (`hasOne`/`belongsTo`), один ко многим (`hasMany`/`belongsTo`), многие ко многим (`belongsToMany`), полиморфные связи.
   - Получение связанных данных выполняется лаконично и естественно:
     ```php
     // Получить всех студентов группы
     $students = $group->students;

     // Получить название группы студента
     $groupTitle = $student->group->title;

     // Создать студента внутри группы
     $group->students()->create(['name' => 'Иван', 'surname' => 'Петров']);
     ```

3. **Автоматическая защита от SQL-инъекций (SQL Injection)**:
   - Все параметры, передаваемые в запросы через Eloquent и Query Builder, автоматически экранируются и передаются через подготовленные выражения PDO (`prepared statements` с плейсхолдерами), исключая риск уязвимостей внедрения вредоносного SQL-кода.

4. **Автоматическое преобразование типов (Attribute Casting)**:
   - Eloquent умеет автоматически приводить сырые строковые значения из БД к нужным PHP-типам (например, `'2023-01-10'` автоматически преобразуется в объект даты `Carbon/CarbonImmutable`, `0`/`1` в `bool`, JSON-строка в PHP-массив `array` или коллекцию).

5. **Решение проблемы N+1 запросов с помощью Eager Loading (жадной загрузки)**:
   - При выводе списка сущностей со связанными данными Eloquent позволяет загрузить все связи за минимальное количество запросов с помощью метода `with()`:
     ```php
     $groups = Group::with('students')->get(); // Всего 2 SQL-запроса вместо N+1
     ```

6. **События жизненного цикла моделей (Model Events & Observers)**:
   - Позволяет легко реагировать на этапы жизни сущности (`creating`, `created`, `updating`, `updated`, `deleting`, `deleted`), автоматизируя логирование, очистку кеша или рассылку уведомлений.

7. **Логическая группировка условий (Query Scopes)** и **Мягкое удаление (Soft Deletes)**:
   - Позволяет инкапсулировать сложные условия фильтрации внутри модели и реализовывать безопасное удаление записей без их физического удаления из БД.

## 4. Инструкция по установке, запуску и проверке

### 4.1. Клонирование и переключение на ветку `homework-2`
```bash
git clone https://github.com/DIana4304/laravel-homework.git
cd laravel-homework
git checkout homework-2
```

### 4.2. Установка зависимостей
```bash
composer install
```

### 4.3. Настройка окружения
```bash
# Windows PowerShell
copy .env.example .env

# Linux / macOS
cp .env.example .env

php artisan key:generate
```

### 4.4. Запуск миграций и наполнение тестовыми данными (сидер)
```bash
# Создание структуры таблиц groups и students
php artisan migrate

# Наполнение базы демонстрационными данными из задания
php artisan db:seed
```

Для подтверждения полной работоспособности всех 7 маршрутов, связей и валидации запустите автотесты:

```bash
php artisan test
```

```bash
php artisan serve
```
