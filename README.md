# Домашнее задание: Установка и настройка Laravel

Репозиторий содержит развернутый с нуля проект на базе актуальной версии фреймворка **Laravel** с выполненными настройками окружения и подробными ответами на теоретические вопросы задания.

---

## 1. Информация о развернутом окружении

- **Версия Laravel (Скелет `laravel/laravel`)**: `v13.11.0`
- **Версия фреймворка (`laravel/framework`)**: `v13.42.0` (актуальная стабильная версия)
- **Версия PHP**: `8.5.10`
- **Версия Composer**: `2.11.2`
- **База данных по умолчанию**: SQLite (`database/database.sqlite`)

---

## 2. Настройка конфигурации (`.env.example` и `.env`)

В соответствии с требованиями технического задания:
1. В стандартном шаблоне конфигурации `.env.example` задано имя проекта и включен режим отладки:
   ```dotenv
   APP_NAME="Laravel Homework"
   APP_ENV=local
   APP_KEY=
   APP_DEBUG=true
   APP_URL=http://localhost:8000
   ```
2. В рабочем файле переменных окружения `.env` применены аналогичные параметры:
   - `APP_NAME="Laravel Homework"` — наименование проекта;
   - `APP_DEBUG=true` — режим отладки включен для отображения подробной информации об ошибках во время разработки;
   - Сгенерирован уникальный ключ шифрования приложения: `APP_KEY=base64:...` с помощью команды `php artisan key:generate`.

> **Важно**: Файл `.env.example` версионируется в Git и служит шаблоном по умолчанию для других разработчиков и серверов развертывания. Файл `.env` добавлен в `.gitignore` и содержит локальные секреты, ключи и доступы к базам данных.

---

## 3. Инструкция по установке и запуску проекта

Для запуска проекта на локальной машине выполните следующие шаги:

1. **Клонирование репозитория**:
   ```bash
   git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ> laravel-homework
   cd laravel-homework
   ```

2. **Установка зависимостей Composer**:
   ```bash
   composer install
   ```

3. **Создание файла окружения**:
   ```bash
   # Windows (PowerShell / CMD)
   copy .env.example .env

   # Linux / macOS
   cp .env.example .env
   ```

4. **Генерация ключа приложения**:
   ```bash
   php artisan key:generate
   ```

5. **Выполнение миграций базы данных**:
   ```bash
   php artisan migrate
   ```

6. **Запуск локального веб-сервера**:
   ```bash
   php artisan serve
   ```
   После выполнения команды сервер станет доступен в браузере по адресу:
   **[http://localhost:8000](http://localhost:8000)**

## 4. Ответы на контрольные вопросы

### Вопрос 1: Перечислите список composer-пакетов, которые использует фреймворк Laravel после установки

После установки чистого проекта Laravel его зависимости разделяются на **основные зависимости рантайма (`require`)** и **зависимости для разработки и тестирования (`require-dev`)**, указанные в файле `composer.json`:

#### 1. Основные зависимости (`require`):
- **`php (^8.3)`** — системное требование к минимальной версии интерпретатора PHP.
- **`laravel/framework (^13.17, установлен 13.42.0)`** — ядро фреймворка Laravel. Включает в себя всю базовую функциональность: маршрутизацию (Routing), ORM Eloquent для работы с базами данных, шаблонизатор Blade, механизм валидации, систему очередей, планировщик задач, события и подписки, промежуточное ПО (Middleware) и контейнер внедрения зависимостей (Service Container / IoC).
- **`laravel/tinker (^3.0, установлен 3.1.0)`** — интерактивная REPL-консоль на базе PsySH. Позволяет выполнять PHP-код, тестировать запросы к БД через Eloquent, вызывать методы сервисов и проверять поведение приложения прямо из командной строки (`php artisan tinker`).

#### 2. Зависимости для разработки и тестирования (`require-dev`):
- **`fakerphp/faker (^1.23, установлен 1.24.1)`** — библиотека для генерации реалистичных фиктивных данных (имена, телефоны, адреса, email, текст) при заполнении базы данных тестовыми данными (сидеры) и в фабриках моделей (`Model Factories`).
- **`laravel/pail (^1.2.5, установлен 1.3.0)`** — инструмент командной строки для удобного просмотра и фильтрации логов приложения в реальном времени прямо в терминале (`php artisan pail`).
- **`laravel/pao (^1.0.6, установлен 1.1.5)`** — пакет Laravel Process & Architecture Optimizer для форматирования и структурирования вывода консольных инструментов тестирования.
- **`laravel/pint (^1.27, установлен 1.32.3)`** — официальный инструмент для автоматической проверки и форматирования стиля PHP-кода (линтер/фиксер) по стандартам Laravel и PSR-12 на базе PHP-CS-Fixer.
- **`mockery/mockery (^1.6, установлен 1.6.15)`** — библиотека для создания имитаций объектов (Mock / Stub) при написании модульных тестов.
- **`nunomaduro/collision (^8.6, установлен 8.9.6)`** — библиотека для красивого, понятного и интерактивного отображения ошибок и исключений (stack trace) в консоли и тестах.
- **`phpunit/phpunit (^12.5.12, установлен 12.5.44)`** — стандартизированный фреймворк для модульного (Unit) и функционального (Feature) автоматизированного тестирования PHP-приложений.

#### 3. Ключевые транзитивные библиотеки (устанавливаемые в `vendor`):
Помимо основных пакетов, фреймворк опирается на проверенные библиотеки экосистемы PHP (всего при установке фиксируется порядка 110 пакетов в `composer.lock`):
- **Компоненты Symfony** (`symfony/http-foundation`, `symfony/http-kernel`, `symfony/routing`, `symfony/console`, `symfony/finder`, `symfony/process`, `symfony/mailer`, `symfony/mime`, `symfony/translation`, `symfony/var-dumper` и др.) — низкоуровневые строительные блоки HTTP-стека, консоли и почты.
- **`monolog/monolog`** — индустриальный стандарт логирования в PHP.
- **`nesbot/carbon`** — расширение стандартного PHP DateTime для удобных операций с датами и временем.
- **`league/flysystem`** — абстрактный уровень работы с файловыми хранилищами (локальная ФС, Amazon S3, FTP).
- **`vlucas/phpdotenv`** — парсинг переменных окружения из файла `.env`.
- **`guzzlehttp/guzzle`** — HTTP-клиент для отправки запросов к внешним REST API.

### Вопрос 2: Изучите директорию config и опишите какие файлы хранятся в этой директории

Директория `config/` содержит конфигурационные файлы приложения. Каждый файл возвращает ассоциативный массив настроек определенной подсистемы фреймворка, значения которых считываются с помощью хелпера `config('file.key')`:

1. **`config/app.php`** — глобальные параметры приложения:
   - имя проекта (`name`), текущее окружение (`env`), режим отладки (`debug`), базовый URL (`url`);
   - часовой пояс (`timezone`), язык интерфейса (`locale`), резервный язык (`fallback_locale`), локаль генератора данных (`faker_locale`);
   - ключ шифрования данных и алгоритм (`key`, `cipher`);
   - параметры режима технического обслуживания (`maintenance`).

2. **`config/auth.php`** — система аутентификации и авторизации:
   - охранники аутентификации (`guards`), определяющие способ проверки подлинности пользователя на запрос (по умолчанию сессионный guard `web`);
   - провайдеры пользователей (`providers`), определяющие способ извлечения учетных записей из базы данных (по умолчанию модель `App\Models\User`);
   - настройки сброса паролей (`passwords`) с указанием таблицы токенов и времени их жизни.

3. **`config/cache.php`** — конфигурация подсистемы кэширования:
   - хранилище кэша по умолчанию (`default`, например `database`, `file`, `redis`, `memcached`, `array`);
   - секции настроек конкретных хранилищ (`stores`);
   - глобальный префикс ключей кэша для предотвращения коллизий при разделении инстансов.

4. **`config/database.php`** — подключение к базам данных:
   - соединение по умолчанию (`default`, в современных версиях по умолчанию используется `sqlite`);
   - параметры подключения для различных СУБД (`connections`: SQLite, MySQL, MariaDB, PostgreSQL, SQL Server), включая хост, порт, имя БД, логин, пароль, кодировку (charset) и префикс таблиц;
   - конфигурация подключения к Redis (`redis`).

5. **`config/filesystems.php`** — настройки дисков файлового хранилища:
   - диск по умолчанию (`default`, например `local`);
   - конфигурация файловых дисков (`disks`: `local`, `public`, `s3`);
   - список символических ссылок (`links`) для автоматического создания симлинка из `public/storage` в `storage/app/public` командой `php artisan storage:link`.

6. **`config/logging.php`** — параметры подсистемы журналирования (логирования):
   - канал по умолчанию (`default`, например `stack`);
   - список каналов (`channels`): `stack` (комбинация каналов), `single` (один файл), `daily` (ротация файлов по дням), `slack` (отправка ошибок в мессенджер), `syslog`, `errorlog` и др.;
   - минимальный уровень логирования (`level`: `debug`, `info`, `notice`, `warning`, `error`, `critical`, `alert`, `emergency`).

7. **`config/mail.php`** — отправка электронной почты:
   - почтовый транспорт по умолчанию (`default`: `smtp`, `sendmail`, `mailgun`, `ses`, `postmark`, `log`, `array`);
   - настройки подключения к почтовым серверам (`mailers`: хост, порт, шифрование, логин, пароль);
   - глобальный адрес и имя отправителя по умолчанию (`from`).

8. **`config/queue.php`** — конфигурация очередей для выполнения фоновых задач:
   - драйвер очереди по умолчанию (`default`: `database`, `redis`, `beanstalkd`, `sqs`, `sync`);
   - детальные настройки подключений к брокерам очередей (`connections`);
   - параметры таблицы для фиксации и повторной обработки завершившихся с ошибкой задач (`failed`).

9. **`config/services.php`** — учетные данные для интеграции со сторонними сервисами:
   - единое место для хранения API-ключей, токенов и секретов внешних провайдеров (таких как Mailgun, Postmark, AWS SES, Resend, Slack и любых пользовательских REST API).

10. **`config/session.php`** — управление пользовательскими HTTP-сессиями:
    - драйвер хранения сессий (`driver`: `database`, `cookie`, `file`, `redis`, `memcached`, `array`);
    - время жизни сессии в минутах (`lifetime`);
    - флаг сброса сессии при закрытии окна браузера (`expire_on_close`);
    - шифрование данных сессии (`encrypt`);
    - параметры Cookie сессии: путь (`path`), домен (`domain`), защита передачи только по HTTPS (`secure`), флаги `http_only` и политика `same_site`.

### Вопрос 3: В какой директории хранятся основные файлы (классы) с бизнес-логикой приложения?

Основные файлы и классы, содержащие бизнес-логику приложения, хранятся в директории **`app/`** (пространство имен `App\`).

#### Организация структуры внутри `app/`:
- **`app/Models/`** — модели Eloquent ORM. Представляют сущности предметной области, инкапсулируют структуру таблиц БД, связи между моделями (relationships), скоупы запросов (scopes), аксессоры, мутаторы и правила манипуляции данными.
- **`app/Http/Controllers/`** — HTTP-контроллеры. Принимают запросы пользователей, взаимодействуют с моделями или сервисами для выполнения операций и возвращают результаты (Blade-шаблоны или JSON-ответы).
- **`app/Providers/`** — сервис-провайдеры (например, `AppServiceProvider.php`). Служат центральным местом для начальной загрузки (bootstrapping) приложения, регистрации зависимостей и сервисов в сервис-контейнере (IoC/DI).

#### Дополнительные директории для бизнес-логики (создаются по мере роста проекта):
- **`app/Services/`** — сервисный слой (Service Layer), куда выносится чистая бизнес-логика из контроллеров для соблюдения принципов Single Responsibility и DRY.
- **`app/Actions/`** — классы действий (Action classes / Single Action Pattern) для изолированного выполнения одной конкретной бизнес-операции.
- **`app/Http/Requests/`** — классы Form Request, инкапсулирующие валидацию входных данных формы и авторизацию действия.
- **`app/Jobs/`** — классы фоновых задач, выполняемых асинхронно через систему очередей.
- **`app/Events/` и `app/Listeners/`** — события и их слушатели, позволяющие реализовывать событийно-ориентированную архитектуру без жесткой связанности компонентов.
- **`app/Policies/`** — классы политик авторизации, определяющие права пользователей на совершение действий над конкретными ресурсами/моделями.
- **`app/Rules/`** — пользовательские правила валидации.
- **`app/Exceptions/`** — пользовательские классы исключений и логика их обработки.
